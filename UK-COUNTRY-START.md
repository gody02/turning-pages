# UK production country start

Production scenario `country-start.uk.mid-2024-v1` starts on 30 June 2024 from immutable demographic package `uk.population.mid-2024.v2` and Human content package `human-content.uk.mid-2024-v1`. It supports childhood at age zero/DOB 30 June 2024 and adulthood at age eighteen/DOB 30 June 2006. These exact anniversaries are authored start rules that preserve annual Clock cadence; they are not observed within-year birth distributions.

`createUkMid2024Game` requires an explicit uint32 root seed. It validates the bundled production packages, compiles the complete 69,281,437-person partition, resolves the selected birth-year cohort, generates `person:1`, and applies optional validated player name and `genderLabel` overrides. The override is identity-facing only. It does not affect naming selection, cohort choice, demographics, statistics, or gameplay mechanics.

The Person is constructed before its legacy compatibility projection. The projection uses the exact-date `createLifeAtDate` initializer, which derives age from the final Person DOB and scenario Clock. Adult mode initializes the established secondary-school, money and adult-start journal values directly; it never calls the legacy `adultStart` transition or temporarily changes authoritative Human state. Childhood retains a truthful start/birth presentation entry because its DOB equals the scenario date. Adult mode records only the adult scenario start. Journal entries are presentation records, not History facts.

The initial Population bridge creates one ordinary cohort-origin request receipt and performs no cohort arithmetic. Ordinary extraction and bootstrap share the same receipt constructor, cohort identity parser, request-key/index rules, Person/cohort birth-year check, and cross-state validation. Calibration's living-membership reservation performs the sole initial decrement. The final state contains 69,281,436 anonymous cohort members plus one living instantiated player, retaining the exact represented total of 69,281,437.

The repository's active gender consumers are limited to UI presentation, identity-content generation, compatibility persistence, migration, and projection validation. No active mechanic interprets root `gender` or `Person.genderLabel` as biological sex or demographic evidence. UK naming source registration-sex categories remain provenance metadata and are combined before gender-neutral content generation.

The bootstrap returns a canonical root-v3 Game with PeopleState v1 and PopulationState v1. Scenario definitions, evidence, reports, and content registries remain runtime content. It creates no History fact, Domain Event, CausalTrace, scheduled occurrence, political career, geography, household, or dynamic demographic flow. Robin and Jamie remain existing legacy compatibility relationship records rather than instantiated Persons.

Existing saves deserialize from their canonical Person and Population state without loading Human generation content. The bundled immutable content registry is required only for a later cohort extraction. Robin and Jamie will eventually be replaced by real Person-backed Relationship/Household/Family systems; this bootstrap neither promotes nor removes them.

The New Game UI is a thin adapter over this domain API. It offers only the production UK scenario and its `childhood`/`adult` modes, obtains one uint32 root seed from platform cryptography per valid submission, and omits blank name or `genderLabel` overrides so generated identity content remains authoritative. It neither computes dates nor names package, profile, cohort or population identifiers. Successful returned Games enter the existing application state and persistence effect unchanged; failures leave the active Game untouched. Other countries remain unavailable until they have frozen country-start paths.
